Decision scope: StillFlow backend product release readiness. This document is evidence-only; it does not add runtime, transport, storage-schema, installer, or frontend behavior.

## Decision

**PASS for the StillFlow backend release boundary, with the client-suite boundary explicitly bounded.**

The backend has a single versioned API contract, a manifest-derived OpenAPI representation, stable sanitized errors, bounded storage/execution/recovery behavior, and a transport-neutral Desktop-local/Web-remote deployment contract. The separate Web/Desktop/CLI client suite remains tracked by Openship Epic #1 and is not represented as shipped by this backend gate.

## H3-02 Protocol — PASS

- `backend/crates/stillflow-api/src/version.rs` defines `API_V1` and the single compile-time `SUPPORTED_API_VERSIONS` list.
- `backend/crates/stillflow-api/src/manifest.rs` defines the authoritative route/schema manifest. `BOOTSTRAP_MANIFEST` aliases that manifest and `openapi_representation()` serializes it; the OpenAPI-facing value is not a second registry.
- Manifest unit tests verify that every route references known request/response schemas and that the serialized representation is derived from the manifest.
- `backend/crates/stillflow-api/tests/e5_g1_runtime_e2e.rs` verifies v1 handshake success, unknown-version fail-closed behavior, and byte-level equality between the OpenAPI representation and manifest serialization.
- `backend/crates/stillflow-api/src/error.rs` exposes the stable sanitized taxonomy: unsupported version, invalid request, not found, conflict, limit exceeded, unauthorized, and internal. Storage, engine, connector, and runtime errors map into that boundary without exposing implementation details.
- `backend/crates/stillflow-api/src/deployment.rs` constructs the Desktop-local and Web-remote transport contract from the same supported versions and manifest; its protocol-equivalence test prevents transport drift.

## H3-03 Code/product completeness — PASS with bounded reviewed unsafe

- A production-source scan on the gate-entry tree found no `TODO`, `FIXME`, `unimplemented!`, or `todo!` markers in backend Rust production paths. Test-only `panic!` assertions are expected test diagnostics, not release placeholders.
- All nine backend crates contain non-empty Rust source trees: API, three connector layers, core, engine, plan, and storage.
- The route manifest contains concrete typed operations with request and response schemas; no placeholder API endpoint was introduced by the route.
- H3 changes are documentation-only, so they add no unsafe code. Existing unsafe sites are confined to reviewed low-level Arrow/Polars FFI and the engine allocator; they are outside this gate's diff and are not treated as an unreviewed H3 addition.
- H1, E5, AUT-J1, AUT-A1, OPS-O4, and H2 evidence consistently identify StillFlow's existing JobRuntime, scheduler, storage, manifest, digest, and authorization authorities. No second canonical algorithm or executor is introduced by this gate.
