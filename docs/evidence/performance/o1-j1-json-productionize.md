## 1. Machine, concurrency policy, and exact commands

Machine (same environment as the O0 round):

| item | value |
| --- | --- |
| CPU | 6 vCPU, 12th Gen Intel(R) Core(TM) i3-12100F |
| Kernel | Linux 6.18.33.2-microsoft-standard-WSL2 |
| RAM | `MemTotal` 12,249,204 KiB (WSL2, ~11.7 GiB) |
| OS | linux (WSL2) |
| Build | `--release`, page cache warm, storage on ext4 via WSL2 |

Both arms ran on ONE binary built at the exact measured head
(`cargo test --release -p stillflow-connector-local-tabular --test
e24_json_a2_prod_evidence --no-run`), arm-selected per invocation via
`E24_JSON_A2_MODE=off|on` (runtime connection-config routing; no compile-time
difference between arms). Every timed run was executed inside the shared
measurement lock `flock /tmp/stillflow-o0-measure.lock`; the arms were
interleaved (off, on, off, on, ...) to distribute machine drift. One warm-up
run per arm convention (the first `off` run) was discarded. Fixture
`e24_primary_100x100k.ndjson` (100 columns × 100,000 rows, deterministic
generator; regenerated by the harness outside the timed window — the timer
starts after fixture generation and stream open, before the first row is
read).

Exact command per run:

```
flock /tmp/stillflow-o0-measure.lock -c \
  'E24_JSON_A2_MODE=off "$BIN" --exact --ignored --nocapture e24_cell_primary'
flock /tmp/stillflow-o0-measure.lock -c \
  'E24_JSON_A2_MODE=on  "$BIN" --exact --ignored --nocapture e24_cell_primary'
```

## 3. Results

| statistic | knob off (generic, production default) | knob on (direct projected) |
| --- | --- | --- |
| P50 wall time | 7.975 s | 4.530 s |
| P95 wall time | 8.371 s | 4.794 s |
| VmHWM range | 41.3–46.9 MiB | 41.0–43.7 MiB |
| envelopes / rows | 25 / 100,000 | 25 / 100,000 |

- **P50 reduction: 43.2%** (P95: 42.7%) — acceptance gate is ≥ 30%.
- Memory boundaries unchanged: VmHWM ranges overlap across arms; the direct
  arm shows no higher high-water mark (the audited bounded-memory shape of
  `direct_projected.rs`, contract §5).
- Identical envelope/row counts across arms on every run (output parity in the
  measurement itself, on top of the runtime differential suite).

## 5. Provenance note

Both arms ran from one binary at one exact head; the arm is a runtime config
value, so the comparison isolates the routing switch with no compile-profile
confound. The knob-off arm is the unmodified generic path (production default
at the production baseline head), so the 43.2% figure is attributable to the
routing switch alone. Sparse/escape-dense/long-string scenarios keep the
#294-disclosed small-gain boundary: the ≥30% gate is claimed ONLY for the
wide-table main scenario measured here.
